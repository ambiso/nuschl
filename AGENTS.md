# Working on Nuschl

Read [SECURITY.md](SECURITY.md), [architecture](docs/architecture.md) and
[development](docs/development.md) before changing dependencies or trust boundaries.

## Writing

Describe what something is or does in comments, documentation, UI copy, commits,
issues, pull requests and reviews. Avoid contrast phrasing and descriptive
negation. State constraints as direct rules.

## Code

- Write the least code that is correct and fast. A large diff is welcome when it
  removes complexity. Reuse before adding; prefer a widely used crate already in
  `Cargo.lock` over new code, and weigh every new dependency as supply-chain risk.
- Use memory-safe Rust. First-party crates keep `unsafe_code = "forbid"` and the
  workspace Clippy rules; SECURITY.md lists the only exceptions. A safe wrapper
  around unsafe code still needs a review of its features and transitive code.
- Parse untrusted content (codecs, images, HTML, formulas) only in the isolated
  workers SECURITY.md names. Only a separate, confined process isolates; extend
  an exception only by changing SECURITY.md with the owner.
- Workers get a fixed executable and arguments, versioned bounded framing, and
  only the files, network, devices and environment their role needs. Fail closed
  when confinement, helper discovery or validation fails.
- Bound inputs and aggregate outputs: bytes, items, decoded pixels, queued work,
  memory, CPU and time. Validate a reply before allocating from its lengths.
- Bind asynchronous results to the connection, conversation and request that
  started them; a result updates only the target it was requested for.
- Keep a child's process credit until it is reaped, also after a requested kill.
- Raw pixels stay in-process or on the device; a browser served over the network
  receives a bounded PNG re-encoded by the worker.
- Only the user's explicit Unmute opens the microphone. Recovery changes only
  Nuschl's own audio resources.
- The browser adapters apply the same validation and budgets; browser codec and
  content Workers get no keys or credentials.

## Tests

- Three layers (#313): `cargo test` unit tests; `cargo test` integration tests with
  real processes on loopback through `nuschl-testkit`; NixOS VM tests for
  whole-system scenarios. Tests belong to these layers only, and every test runs
  in CI or is listed as local-only with a reason.
- A missing test dependency fails the test.
- Keep secrets, credentials, recordings and profiles out of the repository.
- Test against owned loopback servers and synthetic media. Host
  microphone, camera, clipboard, profiles and recordings need explicit task scope.
- Run the relevant tests locally; the `ci` check confirms. Report build, unit, VM
  and physical-device results as what they are, and keep failed runs' diagnostics.

## Builds

- CI is one command that runs the same locally: `nix build -f ci.nix`.
- The crate2nix graph is generated: regenerate it with `just crate2nix`.
- Use the Nix and cargo defaults for parallelism. Keep scratch on disk and stop
  your own build when `/tmp` or available memory falls below 8 GiB.

## Changes and issues

- Changes reach `main` only through pull requests from this repository's branches
  whose required checks pass.
- Work in your own jj workspace. Keep contributors' authorship when replaying
  their work, and add commits on top of others' branches.
- End every agent-written GitHub issue, pull request and comment with a blank
  line, `---`, then `<sub>🤖 LLM-generated by Codex</sub>` (or `Claude`, `Mistral`).
- `just queue` lists approved open issues by priority label, then thumbs-up:
  owner requests, issues labelled `status:approved` or `source:user-request`, and
  the TODO scopes the owner approved (`docs/todo-issue-map.tsv`). Take work from
  its top. Label other proposals `status:needs-approval`.
- Keep potential security findings out of public issues, pull requests, docs and
  commits; use private vulnerability reports.
- `docs/history/` is frozen.
- With several agents, agree on file ownership through the coordinator before
  editing; the coordinator owns integration. Check the coordination inbox at turn
  start and before yielding.
